# 要件定義書(danmaku-game)

作成日: 2026-10-15 / ステータス: ドラフト(現状把握+未決事項)

この文書は、2026-10-15 時点のコードから読み取れる仕様と、まだ決まっていない事項を整理したもの。決まった内容は「未決事項」から「確定要件」へ移していく。

## 1. 目的と前提

| 項目 | 内容 |
|---|---|
| 目的 | 趣味(1本目)。自分が楽しく作れることを優先する。広告などの収益は副産物として、できれば得られる程度に考える |
| ジャンル | 2D縦スクロール弾幕シューティング |
| エンジン | Unity 6(6000.3.11f1)/ URP 17.3 / Input System 1.19 |
| 対象環境 | Web公開(Unity WebGL)。PCのブラウザで遊べること(R-10) |
| 規模 | 3ステージ・難易度3段階。公開後の追加開発はなし(R-18〜R-21) |

## 2. 現状仕様(コードから確認できる範囲)

### 2.1 画面遷移

```
TitleScene --[スタート]--> GameScene --[被弾]--> GameOverScene --[リトライ]--> GameScene
                                     --[ボス撃破]--> StageClearScene --[リトライ/タイトル]--> GameScene / TitleScene
```

- `TitleManager`: スタートで GameScene へ遷移。設定ボタンは未実装(処理が空)
- `StageClearManager`: リトライで GameScene、タイトルで TitleScene へ遷移
- `RetryManager`: GameOver 画面のリトライで GameScene へ遷移
- ボス撃破から StageClearScene への遷移は、`Assets` 内のスクリプトに該当処理が見つからない(未実装、またはシーン側の設定の可能性。要確認)

### 2.2 自機(`PlayerController`)

- 移動: マウスカーソル位置へ直接追従(慣性なし)。画面端でクランプ
- 攻撃: 入力アクション `Fire` を押すたびに1発発射(自動連射なし、発射間隔の制限なし)
- 被弾: レイヤー `EnemyBullet` に触れた時点で GameOverScene へ遷移(1発で終了。体力・残機なし)
- ポーズ: P キーで切り替え(`PauseManager`、`Time.timeScale` を 0 にする)

### 2.3 敵(`Enemy` 抽象クラス)

- 共通: HP、移動、定期的な弾の発射、画面外判定(|x|>3 または |y|>6 で消滅)
- 被弾: レイヤー `PlayerBullet` に触れるとHPが1減る。0になると撃破

| 種類 | 動き |
|---|---|
| `EnemyStraight` | 真下へ直進 |
| `EnemyFloat` | 横から入場→ 一定時間その場で漂う→ 退場 |
| `EnemyCircleOrbit` | 中心点が横移動しつつ、円を描いて動く |
| `EnemyHoming` | 自機へ向かって追尾 |

### 2.4 ウェーブ(`WaveManager` / `WaveData`)

- `WaveData` の配列を順に実行。1ウェーブは「敵Prefab・出現数・出現間隔」で定義
- 出現位置は x が -2.5〜2.5 のランダム、y は 6 で固定
- 現ウェーブの敵が全員いなくなるまで待ち、クールダウン 3 秒の後に次へ進む
- 全ウェーブ終了後にボスを出現させる

### 2.5 ボス(`Boss`)

- HP 100。出現後に y=4 まで降下し、2 秒待機してから攻撃開始。以降は左右に往復
- HP が 66% 以下で第2形態、33% 以下で第3形態へ移行

| 形態 | 攻撃 |
|---|---|
| 1 | 全方位弾(12発) |
| 2 | 渦巻き弾(弾速・発射間隔が大きく上がる) |
| 3 | 渦巻き弾を逆位相で2本 |

### 2.6 弾幕パターン(`BulletPatternManager`)

自機狙い / 扇状 / 直進 / 全方位 / 渦巻き の5種類。

## 3. 現状の課題(コードから見えたもの)

要件ではなく、決めるときの材料。優先度は未設定。

1. 勝利条件の遷移が見当たらない(2.1 参照)
2. 画面外に出た敵も「撃破」として数えるため、ウェーブ完了の判定が撃破と区別されない
3. ボスは `remainingEnemies` に加算されず、撃破時に値が負になる
4. 自機は1発被弾で終了し、スコア・体力・残機・ボムがない
5. 画面範囲(|x|<3、|y|<6)と出現位置が各スクリプトに直書きされている
6. テストがない
7. `.cs` が Shift-JIS で保存されている可能性が高い(CLAUDE.md 参照)

## 4. 機能要件

### 4.1 確定要件
2 章の現状仕様を基本とし、決定ごとに本節へ追記する。

| ID | 要件 | 決定日 | 理由 |
|---|---|---|---|
| R-01 | 被弾ルールは「残機制+ボム」とする。被弾で残機が1減り、残機が0になった状態で被弾するとゲームオーバー。ボムは弾消しとして使える | 2026-10-15 | 弾幕STGらしさを出しつつ、一撃死より遊びやすくするため |
| R-02 | 初期残機は3 | 2026-10-15 | 弾幕STGの標準的な値で、緊張感と遠戦のバランスが取りやすい |
| R-03 | 被弾後は2秒間の無敵(点滅で表示) | 2026-10-15 | 連続被弾を防ぎつつ、緊張感を損なわない |
| R-04 | ボムは初期3つ。被弾して残機を失うと、ボムは3に戻る。アイテムによる入手は行わない | 2026-10-15 | ドロップの仕組みを追加せず、実装を軽くするため |
| R-05 | ボムの効果は「画面内の敵弾を全消去」+「敵(ボス含む)へのダメージ」 | 2026-10-15 | 守りだけでなく攻めにも使える手段にするため |

| R-06 | ボムのダメージは、敵1体あたりボス最大HPの5%(HP100なら5)。雑魚は耐久を超えるため実質一掃される | 2026-10-15 | ボス戦での決定打にならないようにし、第2・第3形態を飛ばせないようにするため |
| R-07 | ボムの発動中、自機は無敵にしない(被弾すれば通常どおり残機が減る) | 2026-10-15 | 弾消しだけで守る手段にとどめ、実装を軽くするため |
| R-08 | ボムの入力は右クリック | 2026-10-15 | マウス移動中でも押しやすいため |
| R-09 | 残機とボムは、画面の隅にアイコンを並べて表示する | 2026-10-15 | 直感的で、弾幕STGの標準的な見せ方のため |
| R-10 | 1本目は趣味開発とし、Unity WebGL でWeb公開する。収益化は副産物として考える | 2026-10-15 | 売上を前提にした事業設計を避け、まず完成させて公開するため |
| R-11 | スコアは「敵の撃破」+「クリアボーナス」で加点する。結果画面(クリア・ゲームオーバー)に表示する | 2026-10-15 | 撃破だけより、被弾やボムの使い方で差がつき、リプレイしたくなるため |
| R-12 | ハイスコアは端末(ブラウザ)内に保存する。オンラインランキングは対象外 | 2026-10-15 | サーバーや不正対策が不要で、WebGL でも動くため |
| R-13 | 自機の攻撃は、ボタン長押しで一定間隔の自動連射とする | 2026-10-15 | 弾幕STGの標準的な操作で、避ける操作と両立しやすいため |
| R-14 | BGM(タイトル・ステージ・ボス戦)と効果音(発射・被弾・撃破・ボム)を入れる | 2026-10-15 | 弾幕STGの手触りと完成度の印象に直結するため |
| R-15 | 音の素材は、フリー素材と Unity Asset Store の無料素材を使う。セールで安い有料素材は、必要に応じて検討する。使う素材は、名称・入手元・ライセンス・クレジット要否を台帳に残す(`docs/assets-ledger.md` を作成予定) | 2026-10-15 | 費用を抑えつつ、公開時の権利トラブルを避けるため |
| R-16 | 設定画面で、BGM と効果音の音量を別々に調整できるようにする(タイトル画面の設定ボタンの用途) | 2026-10-15 | 公開した際、音量への不満を減らすため |
| R-17 | WebGL では、タイトル画面のクリックで開始し、音の再生もそこから始める | 2026-10-15 | ブラウザのユーザー操作前の自動再生制限を避けるため |
| R-18 | 公開時点のステージ数は3(各ステージは、ウェーブ→ボスの構成) | 2026-10-15 | 1本目として、遊びごたえと完成までの距離のバランスを取るため |
| R-19 | 難易度は3段階とし、タイトルまたは開始時に選べる。名称は「ふつう」「とってもむずかしい」「極」の3つ | 2026-10-15 | 弾幕STGとしての挑戦の幅を持たせるため |
| R-20 | 公開後の追加開発(ステージ追加・アップデート)は行わない。公開をもって完了とする | 2026-10-15 | 1本目として区切りをつけ、次作の判断材料にするため |
| R-22 | Unity と Claude の連携は、公式の Unity MCP(パッケージ `com.unity.ai.assistant`)で行う。導入と Claude Code への登録は完了。動作確認は未実施 | 2026-10-15 | 第三者のコードを入れずに、Unity エディタの状態を Claude から確認できるようにするため |
| R-23 | `Assets/Scripts/*.cs` の文字コードを、Shift-JIS から UTF-8 に統一する。変換後は Unity でコンパイルエラーが無いことを確認し、変換だけの変更として単独でコミットする | 2026-10-15 | 以後の編集で日本語コメントが文字化けするのを防ぐため |
| R-21 | 完成の基準は「気が済むまで」とする。ただし、2026年内(2026-12-31)の公開を目標とする。目標に間に合わない場合は、範囲を削って公開する(削る順番は未決) | 2026-10-15 | 趣味として納得感を保ちつつ、終わりが見えなくなることを防ぐため |
| R-24 | 被弾した瞬間に、画面内の敵弾は消さない。無敵の2秒間(R-03)で、連続被弾を防ぐ | 2026-10-15 | 実装を軽くし、ボム(R-05)の弾消しとの役割を分けるため |
| R-25 | ボムの演出(見た目)は、最初の実装では入れない。弾消しとダメージの効果だけを即時に適用する。見た目は、音の導入(R-14)以降に別途決める | 2026-10-15 | 効果の動作確認を先に済ませ、見た目で作業が止まるのを防ぐため |
| R-26 | ボス撃破後は、2秒待ってから StageClearScene へ遷移する。撃破演出は入れない | 2026-10-15 | 撃破の余韻を最低限だけ作り、実装を軽くするため |
| R-27 | 残機アイコンは Player の Sprite を縮小して流用し、ボムアイコンは黄色い丸とする(仮)。新しい画像素材は使わず、後から差し替えられる作りにする | 2026-10-15 | 素材の準備を待たずに HUD(R-09)を動かすため |
| R-28 | ボムは、残数がある限り連打できる。クールダウンは設けない | 2026-10-15 | 仕様を単純にし、残数(R-04)だけで使用回数を制限するため |

R-01〜R-17 で未決の詳細:
- ボムの演出の見た目(効果音は R-14 に含む)
- 使用する具体的な音素材(曲数、雰囲気、入手元)
- 設定画面の項目(音量以外に、キー設定などを入れるか)
- 敵の種類ごとの撃破点、ボス撃破点
- クリアボーナスの計算式(例: 残機・ボム残数・無被弾・クリア時間のどれを加点するか)
- 自動連射の発射間隔、同時に出る自機弾の上限
- ハイスコアを保存する単位(全体で1つか、難易度などで分けるか)。WebGL では PlayerPrefs が使えるが、ブラウザのデータを消すと消える

注意点:
- R-07 により、ボムは「撃てば安全」な手段ではない。発動と同時に敵弾が消えるので、実際に守れる範囲は弾消しの効果で決まる
- R-04(被弾でボムが3に戻る)と R-06 の組み合わせで、ボス戦でわざと被弾してボムを補充する戦術が成立しうる。成立した場合の扱い(許容するか、補充の条件を変えるか)は、実装後のプレイで判断する
